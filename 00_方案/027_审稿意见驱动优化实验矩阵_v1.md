# 027 审稿意见驱动优化实验矩阵 v1

## 主问题

在同一批测试样本、相同实际回退数量和相同 Fast/Full 检测器下，风险排序是否比随机升级更有效地分配局部检测预算？

## 终点与固定条件

| 项目 | 规定 |
|---|---|
| 主终点 | image-level AUROC 的 Risk−Random 配对差值 |
| 次终点 | Recall@5%FPR、实际回退率、端到端 P50/P95、pixel-AUROC、PRO |
| 固定因素 | MVTec AD 划分、Fast/Full backbone、memory bank、图像预处理、seed |
| 统计单位 | 类别—seed 单元；同时报告类别聚类和 seed-level 汇总 |
| 阈值来源 | 仅使用 train/good 的 held-out normal validation |
| Random 控制 | 与 Risk 精确匹配 fallback 数量的无放回随机采样 |
| Oracle | 仅作为 test-label upper bound，不进入主结论 |

## 单变量实验矩阵

| Run ID | 变化因素 | 条件 | 目的 | 状态 |
|---|---|---|---|---|
| M0 | 无 | Fast only / Full only | 质量上下界 | 已完成 |
| M1 | 路由信号 | Risk fast score | 主方法 | 已完成，需用精确匹配协议复核 |
| M2 | 路由信号 | Random matched | 公平控制 | 已完成，需用精确匹配协议复核 |
| M3 | 路由信号 | Score-ranked matched | 风险排序上界/替代门控 | 接口已实现，需正式汇总 |
| M4 | 路由信号 | Oracle label matched | 仅理论上界 | 接口已实现，需单独报告 |
| L1 | 延迟条件 | 正式 memory bank + 100 repeats | 纠正 bank=20 口径问题 | 远端运行中 |
| P1 | 定位指标 | Full pixel-AUROC + PRO | 统一定位证据 | 已完成 |
| D1 | 泛化 | 外部工业数据或正常分布扰动 | 验证部署边界 | 当前缺数据 |

## 预注册解释规则

1. Risk > Random 只支持“风险分配优于随机分配”。
2. Risk < Full 是预期的质量—预算折衷，不作为失败。
3. Risk P95 > Full 时，不得使用“逐样本加速”表述。
4. MVTec 单数据集结果不得外推为所有工业场景泛化。
5. PRO 只在有完整像素分数图和测试 mask 时计算。
