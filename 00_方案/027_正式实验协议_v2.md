# 027｜可靠性约束的自适应 Token 分配：正式实验协议 v2

## 1. 研究问题

在相同模型容量、训练预算和真实 GPU 延迟预算下，经过校准的输入难度与预测不确定性能否驱动可靠的 Token 计算分配，并在固定 P95 延迟预算下改善最坏难例准确率？

## 2. 预注册假设

- **H1**：在固定 P95 GPU 延迟预算下，本文方法总体准确率高于固定稀疏基线。
- **H2**：difficulty 与经过校准的 uncertainty 联合门控能将更多计算分配给真实难例，同时保持易例低成本。
- **H3**：去掉任一门控分支或随机化门控后，Pareto 优势显著减弱。
- **H4**：收益在至少两个输入长度/噪声条件和一个外部数据集方向一致。

## 3. 数据与任务

### 3.1 主数据

- ImageNet-100，固定 train/validation/test 划分；CIFAR-100 只用于 smoke 和机制筛查。
- 使用小型 ViT 或 DeiT-Tiny；patch 数、层数、隐藏维度和训练步数固定。
- 训练阶段只用训练集；稀疏率、门控阈值和延迟预算只由 validation 决定。

### 3.2 难度与压力

- clean CIFAR-100：按预测熵、margin 和错误标签分成 easy/medium/hard。
- CIFAR-100-C：只作为压力测试，不用于训练门控阈值。
- 噪声/遮挡/blur severity：1、3、5。
- 输入长度：标准 patch 数、1.5× patch 数和 2× patch 数的等价序列设置。

## 4. 方法定义

### 4.1 固定模型

使用同一 backbone 和同一分类头。只改变 attention/token 选择策略，不改变宽度、深度、训练数据和训练轮数。

### 4.2 本文方法：RATA-ViT

由 difficulty head 和 uncertainty head 输出两个归一化分数：

```text
d(x) = difficulty head(x)
u(x) = predictive uncertainty(x)
k(x) = clip(k_min, k_max,
            round(k_base * (1 + a*d(x) + b*u(x))))
```

先用 cheap router 估计样本级预算，再进行 token 级选择。`a`、`b`、`k_min`、`k_max` 和延迟控制器只由 validation 预注册网格选择。temperature scaling 只用 validation 拟合。所有实验必须记录 router、token gather、attention 计算的总 GPU event 延迟。

## 5. 对比方法

### 5.1 基线

- Full Attention：准确率上限和延迟参考。
- A-ViT：难度感知的动态计算基线。
- HeatViT：硬件感知 token pruning 基线。
- Adaptive Sparse ViT：可学习阈值和 budget-aware 基线。
- DivPrune：多样性目标的 token 选择基线。
- Fixed Sparse Attention：固定保留率 20%、40%、60%、80%。
- Random Token Drop：相同平均保留率的随机选择。
- Local Attention：固定局部窗口。
- Linformer 或 Performer：选择一个可稳定运行的线性注意力基线。

### 5.2 必做消融

| 消融 | 仅改变的变量 | 目的 |
|---|---|---|
| `-difficulty` | 去掉 difficulty 分支 | 验证输入难度作用 |
| `-uncertainty` | 去掉 uncertainty 分支 | 验证不确定性作用 |
| `random-gate` | 随机化门控排序 | 排除随机稀疏收益 |
| `fixed-policy` | 使用固定 k | 验证动态分配必要性 |
| `global-score` | 用全局分数替代 token 分数 | 验证 token 级门控必要性 |
| `cross-model` | 更换轻量 backbone | 检查架构特异性 |

## 6. 指标与统计

主终点：

- 固定 P95 延迟预算下的 Top-1 accuracy。
- 固定 P95 延迟预算下最坏 10% 难例 accuracy。

次终点：

- 平均准确率和最坏 10% 难例准确率；
- token 保留率；
- P50/P95 延迟；
- 峰值显存；
- throughput；
- energy proxy；
- ECE；
- corruption severity 分层准确率。

每个 seed 使用相同测试样本和同一延迟基准脚本。方法间准确率差异使用 paired bootstrap 10,000 次，报告 95% CI、效应量和 Holm 校正后的多重比较结果。延迟报告中位数、IQR 和 P95，不用 FLOPs 代替真实延迟。

## 7. 成功与失败判据

- 若在固定 P95 延迟下总体准确率和最坏 10% 难例准确率均达到至少 1 个百分点 MID 且 CI 不跨 0，支持 H1。
- 若平均准确率提升但最坏 10% 难例下降，不得宣称可靠效率提升。
- 若理论 FLOPs 降低但实际 P95 延迟不降，结论只能写成理论计算量变化。
- 若 `-difficulty`、`-uncertainty` 和完整方法无差异，核心机制不成立。
- 若收益只存在于 CIFAR-100，不扩展为跨数据集普遍结论。

## 8. 外部验证

主实验和消融锁定后，只运行一次 ImageNet-1K held-out 100 类外部验证。外部数据不得用于修改稀疏率、门控阈值、模型结构或案例选择。
