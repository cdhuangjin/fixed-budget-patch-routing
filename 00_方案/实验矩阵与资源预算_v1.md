# 027｜实验矩阵与资源预算 v1

## 1. 固定配置

| 项目 | 设置 |
|---|---|
| 主数据 | CIFAR-100 |
| 外部数据 | ImageNet-1K held-out 100 类 |
| Backbone | ViT/DeiT-Tiny，单一固定版本 |
| Seed | 5、17、29、41、53 |
| 稀疏率 | 20%、40%、60%、80% |
| 延迟测量 | RTX 5090 D，warm-up 后 GPU event，batch 固定 |
| 主终点 | 固定 P50/P95 延迟下准确率 |

## 2. 运行矩阵

| 阶段 | 方法/条件 | Seed | 目的 |
|---|---|---:|---|
| S0 | full attention，50 step smoke | 5 | 验证训练和延迟测量 |
| S1 | full、fixed sparse、random drop、local、linear attention | 5 | 基线筛查 |
| S2 | difficulty-only、uncertainty-only、联合方法 | 5 | 门控机制筛查 |
| S3 | 通过 S2 的方法 | 5 个 | 正式主实验 |
| S4 | 全部单变量消融 | 5 个 | 机制验证 |
| S5 | CIFAR-100-C severity 1/3/5 | 3 个 | 压力测试 |
| S6 | ImageNet-1K held-out 100 类 | 3 个 | 外部验证 |

## 3. 资源预算

| 阶段 | 估计 GPU 小时 | 存储 |
|---|---:|---:|
| S0 smoke | 0.5–1 | <1 GB |
| S1 基线 | 3–6 | 5–10 GB |
| S2 门控筛查 | 3–6 | 5–10 GB |
| S3 主实验 | 8–16 | 10–18 GB |
| S4 消融 | 8–16 | 10–18 GB |
| S5 压力测试 | 3–6 | 5–8 GB |
| S6 外部验证 | 5–10 | 8–15 GB |
| **总计** | **约 30–61** | **约 35–70 GB** |

50GB 数据盘约束下，每个运行只保留最终 checkpoint、训练曲线、逐样本预测、延迟摘要和资源日志。不要为每种稀疏率保存完整重复 checkpoint；完成分析并确认可恢复前不删除原始结果。

## 4. 执行顺序

1. S0 先验证真实 GPU event 延迟，而不是先跑大规模训练。
2. S1 确认 full attention 和固定稀疏率的准确率—延迟方向合理。
3. S2 只用 validation 选择门控网格。
4. S3 锁定方法和阈值后扩展到 5 seeds。
5. S4 用同一预测文件和同一延迟脚本完成消融。
6. S5 做 corruption 压力测试。
7. S6 只运行一次 ImageNet-100 外部验证。
