## 3. 已排除的创新表述

以下表述不再使用：

- 首次提出自适应稀疏注意力；
- 首次根据输入难度分配 token 计算；
- 首次在真实 GPU 上评估 token pruning；
- 首次建立 accuracy–latency Pareto 曲线。

这些内容已经分别被 A-ViT、HeatViT、Adaptive Sparse ViT、DivPrune 或相关动态 pruning 工作覆盖。

## 4. 可保留的研究缺口

### 缺口 A：尾延迟约束下的可靠计算分配

现有方法已经研究平均效率、理论 FLOPs 或特定硬件加速。027 应把主约束改为真实 GPU 的 P95 latency，并考察 router、token gather、kernel 利用率和 attention 计算的总开销。

置信度：**中等**。需要继续核对近期硬件协同 token pruning 工作，不能写成绝对空白。

### 缺口 B：不确定性校准与难例计算预算的联合

难度或 attention saliency 不等于错误风险。027 可以检验：经过 temperature scaling/ECE 校准的不确定性，是否能把更多计算稳定地分配给真正的难例，而不是只增加平均 token 数。

置信度：**中等**。不确定性驱动计算已有相邻研究，因此贡献重点应是联合校准、风险指标和公平预算，而非单独使用 uncertainty。

### 缺口 C：最坏难例而非平均准确率

已有效率论文常以平均 accuracy、平均 throughput 或平均延迟为主。027 可以预注册最坏 10% 难例准确率，并在固定 P95 延迟下比较风险—延迟 Pareto 前沿。

置信度：**中等偏高**。这是较稳妥的评价创新，但仍不能单独包装成算法首创。

## 5. 修订后的研究问题

> 在固定真实 P95 GPU 延迟预算下，联合校准输入难度与预测不确定性的自适应 Token 分配，能否改善最坏难例准确率，同时保持总体准确率不下降？

## 6. 修订后的方法主张

建议方法名称暂定：**RATA-ViT（Reliability-Constrained Adaptive Token Allocation for ViT）**。

方法链条：

```text
cheap router
→ difficulty / uncertainty calibration
→ sample-level compute budget
→ token-level selection
→ P95 latency controller
→ risk–latency evaluation
```

训练或阈值选择必须使用验证集，测试集只用于一次正式评估。

## 7. 必须加入的强基线

- Full Attention；
- A-ViT；
- HeatViT 或其可复现的视觉 token pruning 版本；
- Adaptive Sparse ViT；
- DivPrune；
- Fixed Sparse；
- Random Token Drop；
- RATA-ViT；
- `-difficulty`、`-uncertainty` 和 `random-gate` 消融。

## 8. 当前裁决

027 可以继续，但应定位为：

> **可靠性约束的尾延迟计算分配与难例评估协议**

而不是“自适应稀疏注意力新方法”。正式主实验应从 CIFAR-100 调整为 ImageNet-100；CIFAR-100 保留为 smoke 和机制验证。若 RATA-ViT 在固定 P95 延迟和最坏 10% 难例上没有优势，应停止扩展，不用平均 FLOPs 改写结论。
